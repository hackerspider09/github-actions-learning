# Chapter 9: Artifacts and Caching

Because GitHub-hosted runners are ephemeral, data is lost when a job completes. Artifacts and Caching are utilized to persist data across workflow execution.

## 1. Artifacts (Data Persistence)

Artifacts allow files or directories generated during a job to be persisted after the job completes. They are used to transfer data between jobs or to retain build outputs for subsequent download.

### Uploading an Artifact
The `upload-artifact` action archives the specified directory or files.
```yaml
jobs:
  build-app:
    runs-on: ubuntu-latest
    steps:
      - run: make build
      
      - name: Archive Build Output
        uses: actions/upload-artifact@v4
        with:
          name: compiled-application
          path: ./build/
```

### Downloading an Artifact
A downstream job can retrieve the archived data using the `download-artifact` action. The downstream job must declare a dependency on the upstream job via the `needs` keyword.
```yaml
  deploy-app:
    runs-on: ubuntu-latest
    needs: build-app
    steps:
      - name: Retrieve Artifact
        uses: actions/download-artifact@v4
        with:
          name: compiled-application
          path: ./deployment-files/
```
*(Reference: `16-artifact.yaml`)*

## 2. Caching (Dependency Optimization)

Caching accelerates workflow execution by storing external dependencies across workflow runs, mitigating the need to re-download unchanged packages from package registries.

### Cache Implementation
The `actions/cache` action manages the storage and retrieval of cached directories. It requires a specific path to cache and a unique key to identify the cache archive.

### Cache Keys and Hashing
Cache keys are typically generated by hashing a dependency lockfile (e.g., `package-lock.json`, `Gemfile.lock`). If the lockfile changes, the hash changes, generating a cache miss and forcing a fresh installation of dependencies.

```yaml
steps:
  - name: Cache Dependencies
    id: cache-dependencies
    uses: actions/cache@v3
    with:
      path: ~/.npm
      key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}

  - name: Install Dependencies
    if: steps.cache-dependencies.outputs.cache-hit != 'true'
    run: npm ci
```
Upon a cache miss, the `npm ci` command executes. Following successful execution of the job, the specified directory is archived under the new cache key for use in future runs.
